🔐 Security Alert Monitoring & Incident Response

A complete, simplified explanation

🛡️ 1. Security Alert Monitoring

Security Alert Monitoring is the continuous observation of systems, networks, and applications to detect suspicious activities or potential security threats. It is usually done by a SOC (Security Operations Center) using SIEM and other monitoring tools.

✔ Key Objectives

Detect unauthorized access

Identify malware or intrusion attempts

Monitor system logs and events

Trigger alerts for suspicious activities

Provide visibility into real-time threats

🧰 Tools Used in Security Monitoring
1. SIEM Tools

These collect logs, correlate events, and generate alerts:

Splunk

IBM QRadar

Microsoft Sentinel

ArcSight

Elastic SIEM

2. EDR/XDR Tools

Monitor endpoints for malware & behavioral anomalies:

CrowdStrike Falcon

SentinelOne

Microsoft Defender

3. Network Monitoring Tools

Zeek (Bro)

Suricata

Wireshark

Snort IDS

🔍 What SOC Monitors

Login failures & brute-force attempts

Privilege escalation

Malware execution

Suspicious outbound connections

File integrity changes

Data exfiltration attempts

Abnormal user activity (impossible travel, unusual login times)

⚠️ Alert Types
1. Informational

Normal events—no action needed.

2. Low Priority Alert

Non-critical misconfigurations.

3. Medium Priority Alert

Suspicious behavior requiring review.

4. High Priority Alert

Potential threats that require immediate action.

5. Critical Alert
Confirmed attack or system compromise.

🚨 2. Incident Response (IR)

Incident Response is the structured approach used to detect, contain, eradicate, and recover from cybersecurity incidents.

🧭 Incident Response Lifecycle (NIST Framework)
1. Preparation

Create IR policies

Set up tools (SIEM, EDR)

Train SOC team

Maintain asset inventory

Conduct tabletop exercises
